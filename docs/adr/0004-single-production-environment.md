# Ambiente único: só produção, sem staging

Este é um projeto de portfólio de pequena escala, com um único deploy real de backend (`https://52-14-171-76.sslip.io`, documentado no `sentinel-auth-api` como instância de "demonstração pública", mas que na prática é o único ambiente que existe ou está planejado). Deliberadamente não introduzimos um `.env` de staging nem um alvo de deploy de staging pra espelhar isso: `.env.development` aponta pro backend local (`http://localhost:8080` via docker compose) e `.env.production` aponta direto pra essa única instância deployada. Um ambiente de staging pode ser introduzido depois, se surgir uma necessidade real — até lá, adicionar um seria infraestrutura especulativa, sem nada de verdade pra validar contra.
